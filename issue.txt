[RUN-001] MATLAB startup failed before any project code executed
First isolated launch exited 134 with Intel OpenMP Error #179:
"Function Can't open SHM2 failed", errno 2 (No such file or directory).
No MATLAB-stage log was created. Investigating sandbox shared-memory/process
visibility. Core dumps are now disabled in the launcher.
Diagnosis: file tracing showed the C runtime rejected the disk-backed /dev/shm
mapping, selected /run for its OpenMP registration object, and hit EROFS.
Resolution: mount a private tmpfs at project/runtime/shm inside the namespace
and make the private /dev/shm point there. This keeps shared-memory objects
within the project's isolated runtime view without writing to host /dev/shm.
The Xvfb socket directory is also pre-created under project/runtime/tmp.
The first symlink setup attempt collided with bwrap's auto-created empty shm
directory. enter_runtime.sh now replaces that private placeholder after setup.
Status: RESOLVED. The init stage completed with exit code 0. All four matrix
dimension checks and the finite-coefficient assertion passed; Ts = 64 ns.
Workspace and figures are saved in artifacts/, log in logs/01_init.log.

[RUN-007] Independent RTL compile: unpacked-array sensitivity expression
Plain Verilog xvlog failed at fpga_lqg_axi_entity_declarations.v:2138:
VRFC 10-634: event expressions must result in a singular type.
The generated AXI logic has an explicit sensitivity list containing the
unpacked array slv_wire_array. The reference repository's pre-generated IP
contains the same line. This is not an introduced LQG algorithm edit.
Retrying xvlog in SystemVerilog mode, without changing any RTL.
Initial compile log is preserved as logs/rtl_compile_verilog_failed.log.
SystemVerilog mode failed at the same statement; its log is preserved as
logs/rtl_compile_systemverilog_failed.log. This is not just a language-mode
configuration issue.
Resolution in the delivery copy only: replace the explicit array-containing
sensitivity list with always @*. This infers sensitivity to all RHS inputs
of the combinational read mux; its RHS and assignments remain unchanged.
No controller arithmetic, register widths, AXI ports, or clocked processes
are changed. The raw generator output remains in work/matlab/netlist_lqg_axitest
and the patched delivery copy is ip_repo/lqg_axi_test. Packaging checksums and
ZIP will be refreshed, then plain-Verilog parsing/elaboration rerun.
Status: RESOLVED IN DELIVERY COPY. xvlog (plain Verilog) and xelab both returned
0; snapshot lqg_ip_elab was built. No compile/elaboration warnings or errors
were present in the final two logs. No simulation stimulus was applied to
that elaborated snapshot; this is not a functional AXI protocol test.
Repackaging returned 0 and reported check_integrity passed / REPACKAGE_SUCCESS.
The exact one-line change is recorded in artifacts/axi_sensitivity.patch.
